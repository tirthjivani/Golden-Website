## 4. Carousel Drag-to-Scroll and Shift + Scroll Navigation
- **Symptom**: 
  - Swiping horizontally or dragging on trackpads did not scroll the carousel horizontally.
  - Scrolling with `Shift + Mouse Wheel` did not transition the carousel.
- **Root Cause**: The carousels use React state (`active` index) and CSS `translateX` transitions instead of standard CSS overflow scrolling, preventing native trackpad and wheel events from scrolling them.
- **Resolution**:
  - Added a `scrollContainerRef` to the outer wrapper of the projects carousel in both pages.
  - Attached a custom non-passive `wheel` event listener in `useEffect` to capture scroll and trackpad gestures.
  - Handled horizontal gestures (`Math.abs(e.deltaX) > Math.abs(e.deltaY)`): moving from right-to-left increments the active project index (`next()`) and moving from left-to-right decrements it (`prev()`).
  - Handled `Shift + Scroll` gestures: scrolling down moves left (`prev()`), scrolling up moves right (`next()`).
  - Added transition cool-down (`800ms`) and called `e.preventDefault()` to avoid vertical window scroll interference during carousel navigation.
- **Validation**: Verified page compile success and local routes responsiveness.

## 5. Project Detail Hero Heading and Subheading Adjustments
- **Symptom**: 
  - Every project detail page (`/project/[slug]`) displayed the intro headline as a subheading under the main project name in the hero section, which looked repetitive since it was already displayed in the central Overview card section.
  - The project title title scrolled away immediately instead of staying pinned visually while scrolling the large hero image viewport.
- **Root Cause**: 
  - The subheading paragraph was hardcoded to display `detail.intro.headline` inside the Hero component in `src/app/project/[slug]/ProjectDetailView.tsx`.
  - The header block was using absolute positioning (`absolute bottom-[calc(50%+30px)] left-[30px]`) making it scroll with the page relative to the container.
- **Resolution**:
  - Removed the `detail.intro.headline` subheading paragraph rendering from the Hero component.
  - Converted the hero viewport content container into an absolute flexbox layout (`absolute inset-0 z-10 flex flex-col justify-end`). Changing it from `relative h-full w-full` to `absolute inset-0` ensures it stretches to the actual resolved height of the parent section including the `min-h-[1280px]` constraint (which `h-full` alone failed to do on shorter viewports), keeping the sticky mask aligned perfectly to the bottom of the section until the image ends.
  - Implemented a full-width sticky container wrapper (`h-[350px] sticky bottom-0`) containing both a background gradient mask and the project title text. The mask has a `40px` bottom bleed (`bottom-[-40px]`) and uses an eased non-linear gradient (`linear-gradient(to top, rgba(0,0,0,1) 0%, rgba(0,0,0,0.9) 15%, rgba(0,0,0,0.65) 40%, rgba(0,0,0,0.3) 65%, rgba(0,0,0,0.1) 85%, rgba(0,0,0,0) 100%)`) which absorbs sub-pixel rendering discrepancies and frame mismatches caused by Lenis smooth scroll inertia, ensuring no bright background slice shows through, while fading out smoothly without a harsh top edge.
  - Decoupled the transition of the mask and the title text by applying the hardware-accelerated scroll-linked transition (lifting by `100px` within the bottom `300px` zone via smoothstep `t * t * (3 - 2 * t)`) only to the title text container (`titleRef`), keeping the sticky wrapper and mask stationary. This ensures the mask stays perfectly pinned to the bottom boundary of the hero section without overflowing into the next section's content, while the text still lifts smoothly to prevent snapping.
- **Validation**: Verified that `/project/golden-heaven` builds correctly, the subheading is removed, the title has a readable dark backdrop, the content container stretches fully, the mask is soft, premium, and stays pinned to the bottom of the hero section without gaps or overlapping card content below, and the text transitions smoothly.
